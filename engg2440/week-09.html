Steady-State Error & Pole Placement

Two halves that meet in the middle: how accurately a loop settles onto its target, and how to choose a controller that puts the closed-loop poles exactly where the transient specifications demand — turning design from trial-and-error into solving equations.

Steady-state error

For a unity-feedback loop the error is $E(s) = R(s) - Y(s)$, and since $Y = RT$, the final value theorem gives two equivalent routes:

$$e_\infty = \lim_{s\to0}sR(s)\,[1 - T(s)] = \lim_{s\to0}\frac{sR(s)}{1 + C(s)G(s)}$$

The second form is the more revealing: error shrinks as the loop gain at low frequency grows. Both assume stability — checking that first is not optional.

Static error constants and system type

Rather than redo the limit each time, define three constants from the open-loop transfer function:

$$K_p = \lim_{s\to0}C(s)G(s) \qquad K_v = \lim_{s\to0}sC(s)G(s) \qquad K_a = \lim_{s\to0}s^2C(s)G(s)$$

and the steady-state error for the three standard inputs follows immediately:

$$\text{step: } e_\infty = \frac{1}{1+K_p} \qquad \text{ramp: } e_\infty = \frac{1}{K_v} \qquad \text{parabola: } e_\infty = \frac{1}{K_a}$$

Which constants are finite depends on the system type — the number of pure integrators $1/s$ in the forward path:

  • Type 0 — finite $K_p$: a step is tracked with a finite error; a ramp is not tracked at all.
  • Type 1 — $K_p = \infty$: a step is tracked exactly; a ramp with finite error.
  • Type 2 — a ramp is tracked exactly; a parabola with finite error.
Why integral action works This is the whole reason the I in PID eliminates steady-state error: adding an integrator raises the system type by one.

Pole placement

Pole locations set the transient response, so rather than tweaking gains and re-checking, choose the closed-loop poles first and then solve for the controller that delivers them. Write the plant as $G = B/A$ and the controller as $C = P/L$; the closed-loop characteristic polynomial is $A L + B P$. Setting it equal to a desired polynomial:

$$A(s)L(s) + B(s)P(s) = A_{cl}(s)$$

Choose $A_{cl}$ from the specifications — typically a dominant second-order pair with the $\zeta$ and $\omega_n$ derived in Week 7, plus any extra poles placed far to the left so they stay non-dominant. Expanding both sides and matching coefficients of each power of $s$ gives a linear system of equations in the unknown controller coefficients.

The controller must have enough free parameters to match every coefficient, which sets the minimum controller order. This polynomial (Diophantine) approach is exactly how PI and PID controllers are designed systematically rather than tuned by hand — and it is the basis of the Week 9 lab.

Freedom cuts both ways A higher-order controller can place more poles, but demands more effort from the actuator and is more sensitive to modelling error. The lecture notes pose this directly: with freedom comes the question of what you actually should choose.
