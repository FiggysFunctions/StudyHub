Week 6 · Lecture notes

Introduction to Control Systems

The control half begins. Having spent five weeks learning to describe how a system behaves, we now ask how to make it behave — measuring the output, feeding it back to a controller, and shaping the response. This week sets up the vocabulary, the objectives and the block-diagram algebra everything else uses.

The elements of a control system

  • Plant — the physical thing being controlled. The first five weeks were about producing a model of it.
  • Control objectives — decided before any hardware: what are we trying to achieve, which variables must be controlled, and to what level of accuracy and speed?
  • Sensors — the eyes of the loop. "If you can measure it, you can control it."
  • Actuators — the muscle, converting the control signal into physical action (a motor driving a manipulator).
  • Control algorithm — the rule computing the action from the error.

Three design objectives

A control system is dynamic: it undergoes a transient before settling into steady state. Analysis and design revolve around three goals:

  1. Transient response — a lift that responds too slowly frustrates passengers, too quickly discomforts them, and oscillating at the destination floor is worse still. Excessive speed can also cause physical damage.
  2. Steady-state error — the lift must stop level enough with the floor for people to walk out.
  3. Stability — without which the other two are meaningless. The total response is the natural response plus the forced response; for a useful system the natural part must decay away, leaving only the forced part.

The design process

Requirements → physical system → schematic → block diagram and transfer function → block-diagram reduction → analysis and design. Modelling produced the transfer function; control uses it to test whether specifications are met and, if not, to change parameters or add components until they are.

Block-diagram algebra

Blocks are unidirectional operators carrying transfer functions. Series blocks multiply, parallel blocks add, and a feedback loop collapses to forward-path-over-one-plus-loop-gain:

$$\text{Series: } \frac{Y}{R} = G_1G_2 \qquad \text{Parallel: } \frac{Y}{R} = G_1 + G_2 \qquad \text{Feedback: } \frac{Y}{R} = \frac{GC}{1 + GCH}$$

With unity feedback ($H = 1$) — the case used throughout this course — that becomes the form you will write more than any other:

$$T(s) = \frac{G(s)C(s)}{1 + G(s)C(s)}$$
Sign matters Negative feedback gives the $1 + GCH$ denominator; positive feedback gives $1 - GCH$. Check the sign at the summing junction before reducing.

Transfer function vocabulary

A transfer function is rational if it is a ratio of polynomials:

$$G(s) = \frac{B(s)}{A(s)} = \frac{b_ms^m + \dots + b_0}{s^n + a_{n-1}s^{n-1} + \dots + a_0}$$

Roots of $B(s)$ are the zeros, roots of $A(s)$ the poles, and the order of the system is $n$. It is proper if $m \le n$, strictly proper if $m < n$ and biproper if $m = n$. Properness matters later: a pure derivative is improper and cannot be built, which is why practical PID controllers need a filter pole.

Standard test signals — step, ramp, parabola and impulse — let different designs be compared on equal terms; the step is the workhorse because both transient and steady-state behaviour are visible in one plot.

Where this leads Week 7 makes the transient response quantitative, defining the specifications a design must hit.
