Guide

Editing & extending your hub

This whole site is plain HTML, CSS and JavaScript that runs from your own files — no internet, no build step, no server. To change anything you open a file in a text editor, edit it, and refresh the page in your browser. Here is everything you need.

1 · Opening the site

Double-click index.html in the top folder and it opens in your browser. Every page links to the others, so from there you can reach any subject. Because it is all local, you can keep the folder in Dropbox, a USB stick, or anywhere you like. To edit, open any .html or .js file in a plain-text editor (VS Code, Notepad++, Sublime, even Notepad). Save, then refresh the browser tab to see the change.

Good to know Adjustable dates are stored by your browser for the downloaded site. If you move the folder to a very different location the saved dates may reset — re-enter your Week 1 Monday on the Assessments page, or use its Export / Import settings buttons to carry your dates across.

2 · How the files are arranged

study-hub/
  index.html          ← hub home, lists your subjects
  README.html         ← this guide
  assets/             ← shared styling + engine (rarely touched)
    styles.css
    hub.js
    katex/  fonts/
  mech2430/           ← one folder per subject
    subject.js        ← the data: equations, glossary, assessments
    index.html        ← subject dashboard
    equations.html  glossary.html  assessments.html  search.html
    week-01.html      ← your weekly notes
    _template.html    ← copy this to start a new week

The pages in a subject (equations, glossary, assessments, search, dashboard) build themselves automatically from subject.js. That one file is where most of your editing happens. The weekly notes pages (week-01.html …) are normal HTML you write by hand.

3 · Writing equations

Anywhere on a page — in notes, glossary definitions, equation entries — just type LaTeX between dollar signs and it renders automatically:

$\sigma = P/A$            inline, sits in the sentence
$$\tau = \frac{T\rho}{J}$$  a centred block on its own line

For example $\sigma = E\varepsilon$ shows as $\sigma = E\varepsilon$. Inside subject.js the equation latex values are written with the helper R\`…\` (a raw string) so you can use single backslashes like \frac and \sigma normally.

4 · Adding a week of notes

Two steps. First, copy _template.html to a new file such as week-02.html and write your notes in it. Then register it in subject.js by adding an entry to the pages array so it appears in the sidebar, dashboard and search:

pages: [
  { f:"week-01.html", week:1, t:"Stress, Strain & Elasticity", … },
  // add this:
  { f:"week-02.html", week:2,
    t:"Torsion of Circular Shafts",
    summary:"One line shown on cards and in search.",
    keywords:"torsion shear shaft polar moment angle of twist",
    related:[
      { type:"eq",  label:"Torsion formula", href:"equations.html#eq-torsion-stress" },
      { type:"def", label:"Polar moment",    href:"glossary.html#g-polar-moment" }
    ]
  }
]

The keywords string is what search matches on, so list the terms you might look for. To link to a glossary term or equation inside your notes, use:

<a class="gloss" href="glossary.html#g-stress">stress</a>
<a class="eqref" href="equations.html#eq-normal-stress">normal stress</a>

Both jump to the target page and show a hover preview of the definition or rendered equation.

5 · Adding an equation

Add an object to the equations array in subject.js. The cat groups it on the Equations page; the id is what you link to with #eq-…:

{ id:"eq-torsion-stress", cat:"Torsional loading",
  name:"Torsional shear stress",
  latex: R`\tau = \dfrac{T\,\rho}{J}`,
  desc:"Shear stress at radius ρ in a circular shaft.",
  vars:[
    { sym:R`\tau`, mean:"shear stress" },
    { sym:"T",     mean:"applied torque" },
    { sym:R`\rho`, mean:"radial distance from centre" },
    { sym:"J",     mean:"polar second moment of area" }
  ],
  links:[ { label:"Week 2", href:"week-02.html" } ],
  keywords:"torsion shaft shear polar"
}

6 · Adding a glossary term

Add to the glossary array. Definitions are HTML, so inline math with \(…\) works inside them. see holds cross-links shown as “See also”:

{ id:"g-polar-moment", term:"Polar second moment of area", sym:"J",
  def:"Geometric property measuring a section's resistance to twisting, \\(J=\\int r^2\\,dA\\).",
  see:[ { label:"Torsion formula", href:"equations.html#eq-torsion-stress" } ]
}

7 · Adding / adjusting assessments

Each entry in the assessments array becomes a card. Dates are not hard-coded — you give the teaching week and an optional day offset, and the page works out the real date from your Week 1 Monday:

{ id:"a-quiz2", name:"Quiz 2", type:"In-class quiz", weight:"25%",
  weekLabel:"Week 8 tutorial",
  dueWeek:8,          // teaching week it falls in
  dueOffsetDays:0,    // 0 = Monday of that week, 4 = Friday
  covers:"Weeks 5–7",
  desc:"Short description.",
  study:[ "Bullet of what to revise", "Another bullet" ],
  weeks:[5,6,7],      // content weeks → auto-linked chips
  related:[ { label:"Stress transformation", href:"week-06.html" } ]
}

The weeks numbers automatically become links to the matching weekly pages. On the Assessments page you can also override any single date with the date picker, or mark a task complete — those are saved in your browser.

8 · Setting the date anchor

Open Assessments and set the Week 1 Monday date at the top to the real first Monday of your semester. Every quiz, the report, and the weekly content all shift to match. You can do this purely in the browser — no file editing — and it sticks. (You can also change the starting default in subject.js under meta.weekOneMonday.)

Moving machines? The anchor date, any due dates you've adjusted, and your "completed" ticks are saved by the browser, not in the files. To carry them to another browser or computer, click Export settings on the Assessments page (it downloads a small .json file), then Import settings on the other machine.

9 · Adding a whole new subject

The easiest path: duplicate the entire mech2430 folder and rename it (e.g. phys1210). Inside the copy, open subject.js and edit the meta, then clear out the example equations, glossary, assessments and pages and fill in your own. Finally, add the subject to the list in the top-level index.html:

window.HUB = {
  subjects: [
    { code:"MECH2430", title:"Mechanics of Solids 1", … , path:"mech2430/index.html" },
    // add this:
    { code:"PHYS1210", title:"Physics 1",
      blurb:"Short description for the card.",
      term:"Semester 2, 2025", tally:"0 weeks",
      path:"phys1210/index.html" }
  ]
};

That is the whole system. Because everything is plain files, you can always open a page's source to see exactly how it was done and copy the pattern.

10 · Archiving a completed subject

The hub home page has an Archived subjects section below your active subjects. Every subject card — active or archived — has an Archive / Restore button in its top-right corner; clicking it moves the subject between the two sections instantly. This choice is saved by your browser (like the assessment dates), so it doesn't touch any files and doesn't need re-doing unless you clear site data.

To set which shelf a new subject starts on by default, add archived: true to its entry in the top-level index.html:

{ code:"MECH3695", title:"Heat Transfer", … , path:"mech3695/index.html",
  archived: true   // starts in the Archived section; still overridable per-browser
}

Archiving is purely about which section a subject is listed in — the subject's pages, search index, and cross-links keep working exactly the same either way.

11 · Linking between subjects

The gloss / eqref hover-preview links from step 4 only work within a subject (they look up the id in that subject's own subject.js). To reference something in a different subject — say, pointing from Thermodynamics to a Heat Transfer equation, archived or not — use a plain link with a relative path up and back down into the other subject's folder:

<a href="../mech3695/equations.html#eq-conduction">conduction (MECH3695)</a>

It jumps straight to that item on the other subject's page; it just won't show the little hover preview, since that only knows about the current subject's data.

12 · Using it on your phone (install as an app)

The hub is a progressive web app: once it's reachable over the web, you can install it to your phone's home screen and it works fully offline — its service worker (sw.js) downloads the entire site to the phone on first visit.

Step 1 — put the folder online. Any static host works; GitHub Pages is free and simple:

  1. Create a repository on github.com (it can be private-source only on paid plans for Pages — a free account means the files are publicly viewable, so keep that in mind).
  2. Upload the contents of this study-hub folder to the repository (so index.html sits at the top level).
  3. In the repository: Settings → Pages → Source: Deploy from a branch → branch main, folder / (root) → Save.
  4. After a minute your site is live at https://<username>.github.io/<repo>/.

(Netlify Drop is even quicker — drag the folder onto app.netlify.com/drop — but GitHub doubles as your backup and makes updates a simple re-upload.)

Step 2 — install on the phone. Open the URL once while online, then:

  • iPhone / iPad (Safari): Share button → Add to Home Screen.
  • Android (Chrome): ⋮ menu → Add to Home screen (or tap the "Install app" prompt).

It now opens full-screen from its own icon and works with no connection — on the train, in the exam-hall corridor, anywhere.

Updating content When you edit existing files and re-upload, phones pick up the changes automatically next time they're online (pages are fetched network-first). If you add or remove files — a new week page, a new subject — run node tools/build-sw.js first so the offline cache list includes them, then upload.
Still works locally None of this changes local use: double-clicking index.html works exactly as before. The app machinery only activates when the site is served over the web.
Backups It is just a folder — zip it occasionally, or keep it in version control / cloud sync, and you will never lose your notes.
